## 2. 原因诊断（不含策略的纯推断仿真）

`scripts/revision/age_error_direction.py` 按 v1 估计器参数复现控制器的年龄推断（每回合重置），只在“观测变化”的步上与真实年龄比较。20 回合 × 1000 步：

| 场景（200–1000 步） | 按顺序到达：命中率 / 平均误差 | 风险率后验 MAP 命中率 | 后验均值偏差 |
|---|---|---|---|
| fixed_delay_8 | 1.00 / 0.00 | 1.00 | −0.13 |
| iid_in_support | 0.68 / 0.35 | 0.87 | +0.01 |
| markov_switching | 0.63 / 0.58 | 0.75 | −0.34 |
| drifting_to_long_delay | 0.42 / 1.20 | 0.71 | −0.00 |
| ood_support_shift | 0.42 / 1.62 | 0.77 | −0.30 |
| ood_changepoint | 0.48 / 1.20 | 0.72 | −0.43 |

1. **年龄推断本身是准的**：后验 MAP 的命中率在所有场景都明显高于“按顺序到达”；开局 50 步与后期差别不大，不是冷启动问题。
2. **但控制表现反过来**：“按顺序到达”永远取可能范围内**最老**的年龄，出错时只会**高估**年龄；后验出错时偏向**低估**年龄（均值偏差为负，MAP 在 IID 下的错误全部是低估）。
3. **假设：年龄误差的代价不对称，低估远比高估有害。**
   - 低估年龄 ≈ 把旧观测当成较新的来用，退化方向就是 direct 策略，而 Hopper 在这个方向上会摔倒（direct 在 IID 下 1663，无时延下 3483）；
   - 高估年龄 ≈ 多往前预测一两步。
   - 佐证：在 IID 下，MAP 命中 87%、“按顺序到达”只有 68%，控制表现却相反（seed 101/102 相对 direct 分别为 +936 和 +1494）；后验掉分最多的场景（Markov、OOD）也正是偏差为负的场景。
4. oracle 仍远高于“按顺序到达”（Markov 3411 vs 2865，drift 3444 vs 2805，OOD 支撑偏移 2316 vs 1543，OOD 变点 3517 vs 2609），所以**仍有很大的改进空间**，只是均值或众数这类对称的决策不对。

这是事后假设，必须先在不同的 seed 上用预注册的实验验证，不能直接写进论文。
